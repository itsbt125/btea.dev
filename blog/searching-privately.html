# what we're trying to solve

Google. We're trying to beat Google at their own game. Google, and every other major search provider, won't hesitate to send your search data to advertisers and law enforcement. Imagine you need to search for a very specific string privately: your search provider now knows exactly where that string came from, along with hundreds of fingerprints on you. I've solved these issues for myself, and in this post I'll detail my private search setup for protection against adversaries and advertisers. To start, you'll need a dedicated Linux server like a Raspberry Pi. I'm not going to go into depth on setting up a Linux distro like Debian on it, but you really only need Docker and a subscription to a private VPN. This article covers routing a private search aggregator (SearXNG) through a VPN provider you trust, like Mullvad.

# the stack

Everything you need runs on a dedicated Linux server, like a Raspberry Pi.

  • SearXNG: a metasearch engine. You type one query, it forwards it to a dozen upstream engines in parallel and merges what comes back. No account, no saved history, no tracking cookies passed through.
  • Gluetun: a Docker container that's basically a WireGuard client with a kill switch baked in. Other containers share its network namespace, so when the tunnel dies they have no internet at all. Nothing leaks out over the home connection "just this once."
  • Mullvad: my VPN provider (it needs to support WireGuard). I use it for the verified no logs claims and privacy stance.

PSA: Search engines stop profiling you, your ISP only sees encrypted traffic to Mullvad, and a target sees a shared exit IP instead of yours. But Mullvad still sees where you connect, so you're moving trust rather than removing it. Good enough against advertisers. This is simply not good enough against a state actor.

# setting it up

The main trick is network_mode: "service:gluetun". SearXNG doesn't get its own network stack, so it can't reach the internet except through the tunnel:

services:
  gluetun:
    image: qmcgaw/gluetun
    cap_add:
      - NET_ADMIN
    devices:
      - /dev/net/tun:/dev/net/tun
    environment:
      - VPN_SERVICE_PROVIDER=mullvad
      - VPN_TYPE=wireguard
      - WIREGUARD_PRIVATE_KEY=REDACTED
      - SERVER_COUNTRIES=Netherlands
    ports:
      - "8080:8080"   # expose SearXNG's port *through* gluetun

  searxng:
    image: searxng/searxng
    network_mode: "service:gluetun"
    volumes:
      - ./searxng:/etc/searxng

Then in settings.yml: turn off the engines you don't use (I keep DuckDuckGo, Brave, Startpage and Wikipedia), disable SafeSearch, and set public: false so your instance doesn't offer itself up as a public one. Mine only answers on my LAN. Running a public metasearch instance is a different hobby.

# proving it works

Test it before you trust it:

docker exec gluetun wget -qO- https://ifconfig.me
# should output with a mullvad exit IP, not your home's public IP.

docker exec gluetun sh -c 'nslookup example.com'
#  DNS queries should also resolve through the tunnel

# browser habits that matter

The private pipe doesn't help if the browser gives you away. Use a privacy hardened Firefox fork like LibreWolf with multi account containers/profiles with no personal logins, and read sensitive results through archive.today instead of clicking straight to the live site. And keep in mind this is only one step: browser fingerprinting, cookies, account correlation and a hundred other things can deanonymize you on their own.

# limits

This is privacy, not anonymity. You're shifting trust from your ISP to your VPN provider, who still sees which IPs you talk to. None of it replaces authorization either: whether the target can see you doesn't change whether you're allowed to test them.

What you get is routine recon that looks like noise, no ad profile of everything you've researched, and an accidental click that can't burn the session. A few dollars/euros a month and an afternoon of config.
